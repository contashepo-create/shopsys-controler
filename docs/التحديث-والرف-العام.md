# التحديث التلقائي ورف الإصدارات العام

المعمارية: **الكود في مستودع خاص، والتحديثات في رف عام بلا كود.**
(نفس منظومة `تَحَكَّم` ↔ `tahakam-releases`، مطبَّقة هنا على `shopsys-controler` ↔ `shopsys-controler-updater`.)

```
┌────────────────────────────┐         ┌──────────────────────────────────────┐
│  shopsys-controler (خاص)   │  نشر    │  shopsys-controler-updater (عام)     │
│  الكود كله + سيرات البناء  │ ──────► │  الإصدارات فقط — لا كود ولا أسرار    │
└────────────────────────────┘         └──────────────────────────────────────┘
                                                        ▲
                                   فحص كل 6 ساعات (بلا توكن) │
                                                  ┌─────┴─────┐
                                                  │  جهازك    │
                                                  │  اللوحة   │
                                                  └───────────┘
```

لماذا هكذا؟ لأن التطبيق يحتاج **قراءة عامة** ليعرف بوجود إصدار جديد بلا توكن مدفون داخله
(التوكن المدفون في مثبّت = ثغرة)، وفي الوقت نفسه لا نريد كشف الكود. الفصل يحلّ الاثنين.

---

## تشغيل أول مرة (ثلاث خطوات يدوية فقط)

1. **سر النشر** — Settings ← Secrets and variables ← Actions ← New repository secret
   - الاسم: `RELEASES_REPO_TOKEN`
   - القيمة: توكن يملك **Contents: Read and write** على `contashepo-create/shopsys-controler-updater`
     (يمكن إعادة استخدام توكن `tahakam-releases` نفسه إن كان توكنًا كلاسيكيًا بصلاحية `repo`).
   - بدون هذا السر: البناء ينجح، وخطوة النشر وحدها تفشل برسالة عربية واضحة — لا إصدار للعملاء.

2. **اجعل المستودع خاصًا** — Settings ← General ← Danger Zone ← Change repository visibility ← Private.
   (لم يُنفَّذ آلياً: التوكن الآلي لا يملك صلاحية تغيير الظهور.)

   وقبلها أو بعدها بسطر واحد: **Settings ← Actions ← General ← Workflow permissions**
   اختر **Read and write permissions** — بدونها لا يستطيع سير `auto-release` دفع التزام
   الإصدار ولا الوسم، وتظهر في السجل رسالة «فشل دفع التزام الإصدار».

3. **ادمج فرع العمل في main** — من واجهة Pull Request. الدمج وحده يُشغّل السلسلة كاملة:
   ترفيع نسخة → وسم → بناء → نشر على الرف العام.

بعد ذلك: **لا شيء يدوي أبدًا** — أي كود يصل `main` يُصدَر ويصل للوحة تلقائيًا.

## كيف يصل التحديث لجهازك؟

| المرحلة | التفصيل |
|---|---|
| الفحص | بعد الإقلاع 12 ثانية، ثم كل 6 ساعات (بلا إزعاج) |
| التنزيل | **في الخلفية** تلقائيًا `autoDownload = true`، ويمكن إخفاء الشريط — التنزيل يستمر |
| التثبيت | **عند إغلاق اللوحة** `autoInstallOnAppQuit = true`، أو فورًا بزر «إعادة التشغيل والتثبيت الآن» |
| البيانات | كلمة المرور والمفاتيح في مجلد بياناتك — التحديث يثبّت فوق القديم ولا يمسّها |

> **مرة واحدة**: النسخ حتى 0.1.2 لا تحتوي وحدة التحديث (وتشير للمستودع القديم) — ثبّت أول إصدار
> على الرف العام يدويًا، وبعدها كل شيء آلي.

## ثوابت لا تُغيَّر (تغييرها = ضياع بيانات المالك)

| الثابت | القيمة | لماذا |
|---|---|---|
| `appId` | `com.contashepo.shopsys-controler` | هوية التثبيت — تغييره يجعل التحديث تثبيتًا جديدًا |
| `name` في `app/package.json` | `shopsys-controler` | منه يُشتق مجلد البيانات `%APPDATA%\shopsys-controler` |
| `deleteAppDataOnUninstall` | `false` | حتى الإزالة لا تحذف المفاتيح |

محمي باختبارات `tests/release_config.test.ts` — أي محاولة لتغييرها تُفشل الاختبارات قبل النشر.

وفوق ذلك: **لقطة احتياطية تلقائية** في `<مجلد البيانات>/config-backups/` عند كل تشغيل تغيّرت فيه
البيانات (آخر 6 لقطات)، مع زرّي «فتح مجلد البيانات» و«نسخة احتياطية الآن» في الإعدادات.
لاسترجاع لقطة: انسخ محتوى أحد مجلدات اللقطات إلى مجلد البيانات نفسه ثم أعد تشغيل اللوحة.

## عند التعطّل (تسلسل الإنعاش)

0. **سير auto-release فشل عند «التزام الإصدار والوسم»**: تأكد من
   Settings ← Actions ← General ← Workflow permissions = **Read and write permissions**
   (وأن `main` غير محمي ضد الدفع).
1. **خطوة النشر فشلت** (السر غير مضبوط أو منتهٍ): أضف/جدّد `RELEASES_REPO_TOKEN`، ثم من تبويب
   Actions اختر التشغيل الفاشل ← **Re-run failed jobs**.
2. **لم يُشغَّل سير البناء أصلًا**: Actions ← «إصدار ويندوز» ← Run workflow ← اختر **الوسم** (لا فرعًا)
   ← Run. الفحوص الداخلية ترفض أي مرجع ليس `vX.Y.Z`.
3. **أُصدر إصدار بنسخة خاطئة**: احذف الوسم (`git push origin :refs/tags/vX.Y.Z`) ثم أعد الدفع؛
   الرفع بـ `--clobber` يستبدل الأصول.
4. **إصدار نُشر بلا `latest.yml`**: ستفشل الخطوة النهائية نفسها — تحقّق من سجل الخطوة، فالفحص
   النهائي يمنع إصدارًا لا يراه أحد.

## تشخيص سريع

```bash
# ما هو الإصدار الأحدث على الرف العام؟
gh release view --repo contashepo-create/shopsys-controler-updater --json tagName,assets

# ما الذي ستقرأه اللوحة فعلاً؟
gh release download --repo contashepo-create/shopsys-controler-updater --pattern latest.yml -O - | head
```
