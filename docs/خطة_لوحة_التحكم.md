## 0) عقد المتطلبات — ما فهمته من المالك (المرجع الوحيد للنطاق)

1. **تطبيق سطح مكتب** (ويندوز، مثبّت **NSIS**، لغة **TypeScript** — نفس لغة shopsys) =
   نسخة احترافية من **بوت تليجرام المطور**.
2. **التحكم في تراخيص العملاء**: إصدار / تجديد / حرق / بحث.
3. **تنشيط وإلغاء تنشيط العملاء** (تفعيل/تعطيل اشتراك العميل).
4. **تفعيل/إلغاء تفعيل قسم أو ميزة إضافية** لكل عميل.
5. **رصد جميع العملاء**: تاريخ آخر ظهور، حالة الاشتراك، والتحكم بهم.
6. **قناة دعم** بين المطور والعملاء (قراءة والرد).
7. **قناة إشعارات**: لعميل واحد / مجموعة / **جميع العملاء** / **عملاء نشاط معين**.
8. **قسم إعدادات** لوضع **مفتاح Cloudflare** — اللوحة تقرأ (وتكتب) من KV مباشرة.
9. **إصدار التراخيص** محلياً و**رفعها إلى Cloudflare**.
10. **العمل بالتزامن مع البوت** — البوت يبقى يعمل بجانبها على نفس البيانات.
11. **إعدادات تغيير كلمة مرور المطور** — مربوطة ببوت تليجرام المطور (رمز OTP).
12. **مستبعد صراحةً**: ❌ **لا نسخ احتياطية** لقواعد بيانات العملاء — ❌ لا وصول لأي
    بيانات محاسبية للعملاء. النطاق = الاشتراك + التراخيص + الميزات + الأقسام + الدعم + الإشعارات فقط.

## 1) التصور (Vision)

**«مركز تحكم المطور — Shopsys Controler»**: تطبيق سطح مكتب مستقل على جهازك الخاص،
نسخة احترافية عمّا يفعله بوت تليجرام المطور اليوم — بواجهة عربية RTL حديثة،
شاشة قفل، وسجل تدقيق، وتقرأ وتكتب مباشرة في Cloudflare KV عبر مفتاح API تضعه أنت في الإعدادات.

- يقرأ ويكتب **مباشرة في Cloudflare KV** عبر مفتاح API تضعه أنت في الإعدادات
  (لا حاجة لتغييرات كبيرة في الـ workers — فقط ختم «آخر ظهور» صغير، انظر §5).
- يوقّع مفاتيح التفعيل **محلياً** (Ed25519) — المفتاح الخاص يبقى على جهازك (مشفر).
- يعمل **بالتزامن** مع البوت: نفس الـ KV، نفس التنسيقات.
- كل عملية حساسة → تأكيد + سجل تدقيق محلي.

## 2) النطاق — ما تفعله اللوحة وما لا تفعله

### ✅ ضمن النطاق
| # | الميزة | آلية التنفيذ |
|---|---|---|
| 1 | تراخيص — إصدار/تجديد/حرق/بحث | توقيع Ed25519 محلي + كتابة `lic:<fingerprint>` و `dev:<deviceId>` في KV |

### تدفق البيانات (v2 — قراءة مباشرة من KV)
```
[أنت] → واجهة (React, RTL)
   │  العمليات → Main Process (Electron)
   │     ├── Cloudflare KV REST API (HTTPS) — مصادقة: Bearer <API Token من الإعدادات>
   │     ├── توقيع Ed25519 محلي (المفتاح الخاص مشفر بـ safeStorage)
   │     └── better-sqlite3: cache + سجل تدقيق
   ↓ HTTPS (Cloudflare API)
[Cloudflare KV — SHOPSYS_CONTROL]   ← dev:* · lic:* · revoked · about · settings:global · notices:*
[Cloudflare KV — SHOPSYS_KV]        ← chat:* (الدعم) · flags:* (Feature flags) · sub:* · revoked (مرآة)
   ↓ (قراءة فقط للعملاء — لا تغيير)
[تطبيق العميل «تَحَكَّم»] ← /about · /revoked · /subscription/:id · /notifications/:id · /support/:id
```

### Namespaces الـ KV (مهم)
| Worker | Namespace | المعرف | الاستخدام |
|---|---|---|---|
| `shopsys-control.mobileshop2026.workers.dev` (devbot) | `SHOPSYS_CONTROL` | `3ed24436e5844f3d9159b5b823cf9b65` (موجود في `tools/devbot/wrangler.toml`) | التراخيص، العملاء، «حول»، إشعارات |
| `shopsys-control.contashepo.workers.dev` (full) | `SHOPSYS_KV` | من لوحة Cloudflare (يضعه المالك في الإعدادات) | الدعم (`chat:*`)، Feature flags (`flags:*`) |

> ملاحظة: عند الحرق أو تعديل «حول» أو «revoked» — اللوحة تكتب في **كلا الـ namespaces** لأن
> الـ workers يقرأون منهما.

## 6) نموذج الأمان

- **Cloudflare API Token**: صلاحياته محصورة — KV read/write للـ namespaces فقط.
  مشفر بـ safeStorage، لا git، لا سجلات، عرض مقنّع.
- **المفتاح الخاص**: على جهازك فقط، مشفر (DPAPI)، توقيع محلي، لا يُرسل أبداً.
- **كلمة المرور**: hash + salt محلي. تغييرها يتطلب **OTP من البوت** (انظر §7).
- **قفل التطبيق**: شاشة قفل (كلمة المرور) — نسخة واحدة فقط (single instance lock).
- **سجل التدقيق**: append-only محلي لكل: إصدار/تجديد/حرق/تفعيل/تعطيل/إشعار/تعديل ميزة/رد دعم/تغيير كلمة مرور/استيراد مفتاح.
- **تأكيد صريح** للعمليات المدمّرة (حرق، إشعار للجميع).
- HTTPS فقط. لا تسجيل لتوكنات/تواقيع/أسرار.
- **الريبو يبقى Private** (موصى به — أداة إصدار تراخيص).
